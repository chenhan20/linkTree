【一、反推出來的命名規則(全文)】

  R1 元素化
     把整趟拆成「路線元素」的時間序列。元素 = 通過一條有名字的路,
     用 data/segment-streams.json 的折線做垂直閘門偵測,正向與反向都算通過。
     另加一個非 Strava 路段的虛擬元素「自強隧道」(見 R6)。

  R2 折返收斂
     一筆通過若「方向與前一筆被保留的同名元素相反」,視為同一趟來回的回程,
     不另計。中社路爬上去(正) + 滑下來(反) = 一次「中」。
     這條是 2026-08-11 的黃金樣本逼出來的:那天中社路實際被通過 9 次
     (4 正 5 反),標題只有 4 個「中」。

  R3 重疊收斂
     兩筆通過在時間上重疊時只留較長的那條路段
     (河濱那三條 Strava 路段彼此包含,不去重會一趟算兩次)。

  R4 換簡稱
     劍=劍南路 中=中社路 風=風櫃嘴 露=(碧山)露營場
     南=南深路 社=社子島(砍鴨頭) 自=自強隧道

  R5 排版
     連續相同的字黏在一起,不同字之間插「一個半形空格」(U+0020,不是全形)。
     例:劍 中中中中 劍 / 自 風 劍 / 劍 中 露

  R6 沒有元素就不改
     一個元素都偵測不到 -> 沿用原本的活動名,報告裡寫 NP / AP。
     (使用者原話:「沒 ITT 路段就預設 先抓原本的 寫個 NP AP 就好」)

  R7 「劍」是雙向的,「中/風/露」的正向才是課
     劍南路無論去程(逆向通過「劍南路回程」路段)或回程(正向)都寫「劍」,
     所以它天然形成「劍 X 劍」的頭尾括號 = 出門走劍南路、回家也走劍南路。
     露營場同理:2026-07-21 / 08-04 是「露 風 露」= 碧山上去、風櫃嘴、碧山下來。


【二、規則驗收(黃金樣本)】

  2026-08-06  人工「劍 中 露」   <->  產生器「劍 中 露」    完全一致
  2026-08-11  人工「劍 中中中中 劍」<->  產生器「劍 中中中中 劍」完全一致

  另外三個使用者口述的規則也被獨立重現(這三天使用者沒寫過標題,
  是產生器自己算出來的,結果剛好落在他描述的模板上):
    「有中社一次 劍南路過去 -> 劍中劍」 -> 05-19 / 05-26 / 05-27 / 06-16 都算出「劍 中 劍」
    「兩次中社就是 劍中中劍」          -> 資料裡沒有剛好兩次的日子;三次的 07-28 算出「劍 中中中 劍」
    「風櫃嘴 可能就是 自風劍 或是 劍風劍」-> 05-21 算出「自 風 劍」、06-23 算出「劍 風 劍」,兩種都出現了


【三、偵測器的正確性交叉驗證】

  把產生器的「正向」通過拿去對 data/itt-segments.json 裡 Strava 官方的
  effort 清單(2026-05 之後共 36 筆),逐筆比對日期 / 起始時刻 / 秒數:
    - 官方有的,產生器全部抓到,沒有漏。
    - 秒數誤差最大 2 秒(閘門插值 vs Strava 自己的取樣)。
    - 產生器沒有多出官方沒有的正向 effort(零誤報)。
  「反向」通過官方沒有對應資料(Strava 路段有方向性),那是這份提案自己加的,
  但它推出來的兩個黃金樣本標題跟人工完全一致,間接驗證了反向偵測是對的。

【五、非公路車 FIT 的處理方式】
================================================================================

data/fit 共 39 個 FIT,依檔名 / _activities.json 的 type 分類:

  20 個 公路車 (18 個「內湖區-公路車」+ 2 個「永和區-公路車」)  -> 本表全部處理
   1 個 室內自行車 (2026-05-17)  -> 排除:無 GPS,不可能有路線元素
  13 個 肌力訓練                -> 排除:非騎乘
   4 個 跑步 (06-10 x2、06-17 x2)-> 排除:非騎乘
   1 個 健行 (2026-05-16 鹿谷鄉) -> 排除:非騎乘

  註:20 趟公路車裡有 3 趟(07-15 / 07-30 / 08-05)沒有進 rides/index.json,
  因為 scripts/build-ride-reports.py 依 _reports.json 的規則把它們 skip 掉了
  (TSS 59 / 51 / 67,低於門檻 100)。它們也剛好是三趟偵測不到任何路線元素的,
  所以就算之後解除 skip,依 R6 也是沿用原標題 + NP/AP,沒有衝突。

【六、低信心案例與原因】
================================================================================

L1  2026-07-22「南 河」— 低
    偵測沒問題(南深路 19:00 正向 + 河濱10K 木柵–永福 19:39 正向,
    南深路那筆對得上官方 1017 s)。低的是「河」這個字:
    使用者從來沒說過河濱路段怎麼縮。「河濱10K 木柵–永福」可以縮成
    河 / 濱 / 木 / 永,四種都講得通。需要拍板。

L2  2026-08-13「黃」— 低
    兩個問題疊在一起:
    (a) 簡稱未確認。「黃港河執行」縮成「黃」是我猜的,也可能是「河」或「淡」。
    (b) 這趟同時觸發「黃港河執行」與「關渡→美堤」兩條路段,它們幾乎是同一段
        河濱(關渡→美堤 是黃港河執行的子集)。我用 R3 留了較長的「黃港河執行」,
        這條規則沒有黃金樣本背書。Strava 官方那天也只認列「黃港河執行」1788 s,
        算是弱佐證。
    (c) 這趟是 51 km / 爬升 112 m 的純平路河濱,使用者的口述規則裡
        「河濱」到底算不算路線元素、還是應該直接走 R6 沿用原標題,沒有交代。

L3  2026-07-21 / 2026-08-04「露 風 露」— 中
    結構偵測是硬的(碧山露營場正向爬 -> 風櫃嘴正向爬 -> 碧山露營場反向下山回家),
    三段的時間、方向、軌跡都對得上。不確定的是「最後那個露要不要寫」:
    使用者說「露營場 風櫃嘴 就照打」,字面上可能只想要「露 風」。
    但依照 R7(劍南路去回都寫成「劍 X 劍」)推類比,寫成「露 風 露」比較一致。
    兩個候選:  露 風 露  (本表採用)  /  露 風
    這題只影響這兩天。

L4  2026-07-14 / 2026-07-16「露」— 中
    單一元素、單字標題。偵測本身很硬(對得上官方 1922 s / 1714 s),
    折返收斂也符合 R2。低的是「使用者會不會覺得單字標題太乾」,
    可能想寫成「露」或「碧山」或「露營場」。純風格問題。

L5  2026-06-18「社」— 中
    同 L4 的單字問題,再加一層:這趟 67 km、爬升 280 m,實際上是
    社子島 -> 淡水河右岸 -> 大稻埕 -> 新店溪 -> 木柵 -> 南港 -> 內湖 的大環線,
    只有開頭 29 分鐘落在「社子島砍鴨頭」路段上。用「社」當整趟的標題,
    覆蓋率只有全程的一小段。可能需要一個「河濱環線」之類的元素才夠描述。

L6  2026-07-23「劍 中 風 露」— 中
    四個不同元素串起來,是資料裡最長的一個標題,沒有同型的黃金樣本。
    每個元素本身信心都高(中社路 1502 s、風櫃嘴 2432 s 都對得上官方),
    但四字標題會不會太長、使用者要不要砍掉接駁性質的「露」,不知道。

L7  「自」= 自強隧道 — 高,但推論鏈值得說明
    這不是 Strava 路段,是我自己加的虛擬元素,證據鏈是:
    (a) 掃全部 20 趟找「GPS 斷訊 >=30 s 且位移 >=250 m」的指紋,
        只有 2026-05-21 命中一次:06:28:11 起斷訊 106 秒、位移 821 m,
        從 (25.08725, 121.54960) 高度 25 m 直接跳到 (25.09460, 121.54879) 高度 20 m。
    (b) 那個位置在大直北安路與士林至誠路之間穿過雞南山,高度全程 20-25 m
        —— 走地面必須翻過 150 m 的劍南路。長度 821 m,跟自強隧道相符。
    (c) 而 2026-05-21 正是使用者口述「自風劍」模板會套上去的日子:

# FIT 分析與中社 PR 訓練審查

日期：2026-09-05。這是研究與建議稿；未修改現行 Python、課表 JSON、歷史報告或原始 FIT。

## 結論

資料底層有價值，尤其原始 FIT、逐段功率、換檔事件與課表對帳。但部分時間序列計算不一致，教練文字也把觀察、模型和因果推論混在一起。先修這些，再用同條件的測驗決定訓練；不宜把「60 分鐘 190W 是能力上限」「中社只有配速問題」「DOMS 70 分一定未恢復」當已證實事實。

本次檢閱解析、評分、HTML 生成、功率曲線、路段偵測、攻略、DOMS、教練 context 與 CI 流程；重算八趟有功率 FIT，另做三個合成案例。不是全歷史 FIT 全量驗證，也未做感測器實體校正。

## 值得保留的設計

- 保存原始 FIT，分析可重跑；處方、評語、量測與 HTML 大致分層。
- `score.py` 對主課逐段對帳，提供時間完成率、區間命中率、前後半功率；比只用整趟 IF 評價一堂課更有用。9/1 做滿時間但門檻段瓦數不足，正好示範兩者需要分開。
- 功率曲線另外有等長 182 天窗口，保留每個最佳值的日期；大缺口切段比移動時間拼接合理。
- 電變用 gear-change 事件還原停留時間，而不是只數換檔次數。未知初始檔位的處理也有考量。
- 路段偵測保留方向、沿途檢查點與多次通過邏輯；FIT 回補和 Strava 成績有來源欄位。
- 程式已有估計值、邊界敏感度、缺功率、缺踏頻等提示。重點是讓教練結論也遵守這些限制。

## 已重現的計算問題

### 1. 最佳 20／60 分鐘可能把停止前後拼接

位置：`tools/tcx/analyze_tcx.py:771` 附近先按速度刪除不移動秒數，`:794` 附近再以同一個 `mw` 算 rolling best。結果代表累計移動秒數，不保證連續時間。

合成案例：300W 騎 10 分 → 停 5 分 → 300W 騎 10 分。報告算法得到最佳 20 分 300W；保留完整時間軸則為 225W。

|---|---:|---:|
| 2025-10-14 | 161.2W | 無足夠長的連續段 |
| 2026-04-28 | 171.6W | 無足夠長的連續段 |
| 2026-08-06 | 178.1W | 無足夠長的連續段 |
| 2026-08-11 | 182.1W | 176.7W |
| 2026-08-13 | 185.2W | 185.2W |

「無足夠長的連續段」不是 0W，也不是能力不足。八趟的最佳 20 分算法差異很小（最多約 0.1W），因此不能宣稱目前中社 PR 或所有短時功率都被灌水。

建議：共用時間軸與有效窗口規則；曲線保留零瓦滑行，長缺口中止窗口，停止不能刪掉後拼成連續紀錄。若要呈現移動時間統計，另列名稱。NP、TSS 的 timer-time 政策也應獨立定義，不能由此推論所有平台都只按速度濾點。

### 2. 長缺口無上限以前值補齊

位置：`analyze_tcx.py:500` 的 `resample_1hz()`。功率、速度、心率甚至座標都會沿用最後一點，雖標 `_gap`，主要功率計算沒有排除它。

合成案例：起點 300W、5 分後下一筆 0W，中間補出約 90kJ。這不代表真實檔案每個缺口都高估；若缺口前是零瓦，影響方向不同。

實測 8/6 原始 8,774 點，補成 11,894 點，最長記錄間隔 1,281 秒。8/25、9/1、9/3 則完整每秒一筆、沒有缺瓦，對這三趟的資料連續性可較放心。

建議：結合 FIT timer 事件，區分停錶、功率遺失、未配對感測器與真實 0W。顯示覆蓋率、最長缺口與窗口有效性。現有 `build-power-curve.py` 把所有 1–8 秒缺口及缺瓦都補 0，也只是保守政策，不能直接稱它們一定在滑行。

### 3. 心率脫鉤定義容易看反，可信度條件太寬

`analyze_tcx.py:613` 算的是 `(後半效率 − 前半效率) / 前半效率`。200W 固定、HR 140→154，輸出 **−9.1%**。這在「效率變化」定義下自洽，但不能讓讀者把它和其他系統正向顯示的疲勞漂移直接比較。

目前只要求前後半平均瓦數差不超過 25%，仍可能把間歇、熱身、停等混在一起。心率與功率的有效樣本也分開取平均，未確保成對覆蓋。

建議：標明公式與正負方向，只分析選定的穩定有氧段，排除熱身、缺訊與停等，搭配溫度、散熱、補給及 RPE。5% 是條件性參考，不是診斷線。TrainingPeaks 也要求穩定有氧段並提醒短段限制。[官方說明](https://help.trainingpeaks.com/hc/en-us/articles/204071724-Aerobic-Decoupling-Pw-Hr-and-Pa-HR-and-Efficiency-Factor-EF)

## 目前訓練診斷需要改寫的地方

### 「20 分 252W → 60 分 190W 的斷崖」尚未證明是唯一限制

`power-curve-windows.json` 生成於 8/30，最近一窗截止 8/27，並非 9/5 即時曲線。舊窗 20 分 252W 來自 **2025-10-02**，60 分 190W 來自 **2025-09-21**，是不同騎乘。新窗的 20 分 246W 是 **2026-05-19**，60 分 191W 是 **2026-06-23**。

這些是觀察到的最佳值，未註記每趟是否新鮮、是否全力或有合適路段。一年沒做 60 分最大測驗，低紀錄不代表只能維持該瓦數；也不能用去年 5 分 321W 排除今年的有氧高強度訓練需求。更不能把 20 分×95% 視為人人固定可維持一小時的關係。[FTP 概念驗證研究](https://pubmed.ncbi.nlm.nih.gov/29801189/)

目前更直接的證據是：9/3 連續 Tempo 平均 **181.6W**、前後半 **181.2→182.1W**，穩定段表現不錯；9/1 在扭力組後做三組 15 分，約 **200.6／189.6／190.1W**，低於 210–220W 處方。這支持「先降低主課前的疲勞、確認裝置，再觀察門檻輸出」，不足以分辨能力、裝置偏移、睡眠、補給各占幾成。

### 不用補 TSS 來宣稱前置疲勞已匹配

9/8 處方為 110 分 @185–195W 加三次 1 分全力，目標 TSS152，理由是逼近 8/11 的 TSS190。兩堂課即使 TSS 相同，也不等於肌肉、代謝、恢復狀態一致；此處還混有籃球、重訓、睡眠與測量來源差異。

8/13「疲勞後 20 分 208.1W」實際為 **911 秒、均瓦211.5W**，再以 `t^-0.06` 外推。9/10 做滿20分可成為新的有效基準，但「增加10／15W就證明補平斷崖」沒有個人重測誤差的支持。plan 的 9/8 文字寫10W，9/10 的結構欄位仍15W，也不一致。

若仍照原協定完成 9/10，可保留為探索性的配對觀察，記清前48小時活動、睡眠、補給、室外環境、實際前60分作功與RPE。我的建議是不要單為湊 TSS 人為增加疲勞，未來重測採可重複的正常準備。這會降低與舊前測的可比性，需公開標記；不能同時宣稱完全配對。

### 15.3 小時／月不是生理門檻

`build-coach-context.py`／`coach-brief.py` 中斜率與損益線是固定數字；context 又承認重算後16.4–17.4h。月時數、測驗機會與eFTP會一起變化，相關性不能推出「少一小時會掉固定幾瓦」。

你4–8月的騎乘量約15.2／12.7／6.1／13.8／16.1h，連續性確實比多加一次爆衝更值得優先處理。但用能恢復、能持續的週頻率規劃，比月底補到某條線更合理。

18:49→16:25 要少144秒，相當於從18:49縮短 **12.8%**。無法保證一個月達成。先確認九月測驗及同條件中社成績，再判十月是否適合正式挑戰。體重資料約76.5→80kg也可能影響爬坡，但風、總重、裝置與配速未控制，不能直接把秒數分攤給各因素。

playbook 的「配速，不是引擎」可改為：**開頭輸出保守可能造成時間損失；目前資料無法排除體能與體重的共同影響。** 它只納入單日單趟且均瓦≥220W 的樣本，舊期n9、新期n7，不能代表全部訓練；8/11 四趟也因此不在該組比較中。

最後一個四分段功率高，不足以證明前面只輸在策略；短末段可以動用剩餘能力。原文 eFTP268→237 並非4.8%，是約11.6%下降，不能接著以此作精確時間歸因。

取消「一律禁用某齒」「8分鐘前HR176就固定減10W」的硬規則。不要故意維持交叉鏈，但踏頻／齒比應服務於可維持功率與舒適度；最輕檔使用率也可能是較低速度的結果。178只是近期觀測最高，不能直接當已測得最大心率。

## 十月四週建議稿

以2026年10月為「下個月」，主週期 **10/5–11/1**，10/1–4作過渡恢復，預定10/27週二測中社。若你指接下來四週，日期需另移；9月原有後測／爬坡日期不會由本稿自動覆蓋。

沿用週二早最多150分、週四早最多120分、週末每次≤60分、週二晚籃球與週三重訓／公司有氧課，週三不排騎車。主表先按籃球／有氧照常存在來排，因此只有一堂單車品質課。

進階不是每週必須發生：工作段RPE約6–8/10、最後一組仍可穩定踩完，隔天恢復正常才加量；第二組已明顯崩落、需硬撐才守住瓦數，當天減5–10W或少一組，下一週不升級。不要為了拿滿分硬做。熱身異常吃力、實際睡眠差、腿部不適時改恢復；HRV／DOMS單一讀數不當唯一開關。

### 如果能調整籃球／有氧課

若週二籃球降為輕鬆、週三有氧改低強度且腿已恢復，第二週週四才可把耐力日**替換**成3×4分約245–260W、組間4分，總60–75分；第一次從下限或較少組數開始，以能控制完成為準。不是加在原110分之後，也不是每週必須做。前週無法完成門檻課時不加這堂。

高強度間歇與累積工作時間能改善自行車能力，但研究不支持直接套一個「最強課表」保證你的四週PR；這裡的劑量是依你的時間、恢復與現有輸出做的保守安排。[自行車間歇隨機試驗](https://pubmed.ncbi.nlm.nih.gov/21812820/)

### 測驗前六天

10/21–26以降低約40–60%騎乘量為參考，保留少量短提速；從前一個同星期區間比較，不拿含測驗的整週反推減量。這段也要降低公司有氧、籃球與腿部重訓的負荷，否則單車減量不代表整體恢復。減量研究支持減少總量、保留部分強度，但你的比例仍需看實際疲勞與平常週量。[耐力減量綜述](https://pubmed.ncbi.nlm.nih.gov/37163550/)

10/27晚不安排高強度籃球。若這點或前一週恢復條件無法做到，中社仍可當訓練測驗，但不宣稱是在準備充分的PR狀態。

### 中社當天怎麼配速

1. 以九月同裝置、同路段的新鮮測驗，選擇今天約能維持17–20分的功率；不能直接照抄去年268W，或照攻略先踩285–311W。
2. 起始1–2分靠近當日計畫均瓦，避免為追PR一開始爆衝；中段盡量穩定，短陡坡可自然小幅加力；最後約3分仍有餘裕再推高。這是待實測的起始策略，不是每種坡形的最優解。
3. 三秒功率看即時控制、lap均瓦看整段，心率與RPE作輔助。不要等心率碰165才決定踩多少，也不要刻意把心率數字衝高。
4. 換到能自然維持輸出的檔位，無須禁止30／34T；不用為80–85rpm精確數字扭曲輸出。
5. 記起終點、裝置／校正、體重、風雨、RPE、補給和是否被交通干擾。用同來源路段秒數比較；18分是階段成果，**16:24或更快**才叫破16:25 PR。

九月若測驗仍落在19分上下，十月的成功可先定義為「同條件變快、完成品質課、恢復可持續」。不要為硬達16:25安排連續疲勞或快速減重。
